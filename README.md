# VIM2

**按一下说话，再按一下，文字就出现在光标处。**

VIM2 是 Windows 本地语音输入工具。它能在记事本、浏览器、聊天软件、IDE 和远程桌面中工作。只需在自己的电脑安装一次，连接不同远程机器时无需重复安装模型。语音识别完全在本机完成，音频和文字不上传，也没有云服务费用。

> 当前支持 Windows 10/11 x64。macOS 支持正在路上。

[第一次使用：查看完整安装手册](INSTALLATION.md)

## 为什么选择 VIM2

- **真正离线：** 模型在本机运行，断网也能识别，语音不离开电脑。
- **一次安装，处处可用：** 连接多少台远程机器都不必重复部署，直接向当前远程桌面输入文字。
- **哪里都能输入：** 不局限于单个编辑器，最终文字直接粘贴到原来的光标处。
- **边说边看：** 录音过程中实时显示预览，停止后再生成可靠的最终文本。
- **中英混合：** 支持中文、英文、中英文混说以及多种中文方言。
- **硬件可选：** 有 NVIDIA GPU 可追求速度或精度，没有独显也能使用 CPU 模型。

## 启动

完成安装后，双击 `Start.cmd`。等待任务栏右下角的 VIM2 托盘图标变为绿色。

双击后没有反应时，查看 `runtime/vim2.log`。安装检查命令为：

```powershell
$env:PYTHONPATH = "$PWD\app"
python -m vim2 --check
```

## 使用

1. 点击任意应用中要输入文字的位置。
2. 按一次右 Alt 开始录音。
3. 再按一次右 Alt 停止；识别完成后文字会自动粘贴。
4. 在本地应用中，录音期间按 Esc 可取消，不会识别或粘贴文字。

右键单击托盘图标可以切换模型、编辑热词或退出。

远程使用时，VIM2 仍然运行在自己的电脑上；请确认远程桌面或远控软件已允许剪贴板同步。远程机器不需要安装 VIM2、Python 或模型。部分 RDP 客户端会直接将 Esc 转发给远程系统，本机 VIM2 无法捕获，因此不支持在 RDP 窗口内使用 Esc 取消录音。

## 模型

| 模型 | 设备 | 特点 |
|---|---|---|
| Qwen3-ASR 0.6B INT8 | CPU | 默认，无需 NVIDIA 显卡 |
| Qwen3-ASR 0.6B FP16 | NVIDIA GPU | 速度和准确率均衡 |
| Qwen3-ASR 1.7B INT8 | NVIDIA GPU | 更高精度，处理速度较慢 |

程序一次只加载一个模型。可在托盘的“识别模型”菜单中切换，选择会自动保存。

超过 30 秒的 GPU 识别输入使用遵循模型音频分块边界的 SDPA 注意力，以改善长录音的识别完整性。30 秒以内的输入保留原有音频注意力路径；这是依据实录回归设置的兼容性边界，不代表所有时长的准确率已经验收。CPU ONNX 模型已在导出模型内处理音频分块，不需要 PyTorch 或额外的对齐模型。

GPU 0.6B 已启用录音期间的草稿验证加速：预览最多使用最近 60 秒音频，只保留最多 512 个草稿 token，不保留预览 GPU 解码缓存。后续预览和停录识别使用同一模型批量验证草稿，最多验证 8 个位置，遇到不匹配立即回滚并逐词纠正；草稿不会强制覆盖最终文字。预填充只计算最后一行词表输出，保留完整隐藏状态和 KV。停录会取消正在执行的预览，但保留上一次成功的草稿；新录音、取消、完成、重试、模型切换和热词重载会清理草稿。

GPU 0.6B 超过 30 秒的输入还限制卷积批次最多为 16 个音频块，并显式展开文本注意力的 KV，避免 GQA 退回高内存计算路径；缓存验证使用已注册的 SDPA 因果掩码，不能让后续草稿词泄露到前面的预测。所有临时设置在成功、失败和取消后恢复。300 秒静音边界测试中，峰值 GPU 分配由约 4.27 GiB 降至 2.02 GiB，推理由约 125 秒降至 1.13 秒；静音不是长语音准确率证据。

此路径保留完整最终音频上下文，不依赖文本接缝切掉已识别音频，因此仍有音频编码和验证成本，并非停录后只编码尾段。约 96 秒实录的最终生产会话测试中，同进程完整识别为 25.60 秒，草稿加速为 15.34 秒（约快 40%），两者文字完全一致；相较此前原始基准，关键主线保留。草稿路径峰值 GPU 分配约 1.68 GiB，未发生 OOM。该数据不是任意时长或其他显存占用下的无 OOM 保证，也不是真实识别准确率评估。超过 512 token 且仍未结束的结果会明确报错并允许重试，不静默截断。CPU 和 GPU 1.7B 暂不启用草稿加速，保持原有实时识别路径。

GPU 1.7B 的隔离草稿实验在 25 秒实录上更快，但约 96 秒录音出现重复生成；增加生成预算、减小验证批次均未解决。关闭 INT8 异常值处理虽更快，却改变了关键归属语义，因此这些实验配置均未启用。不要以短片段加速结果替代长录音验收。

0.6B 的卷积批次和文本注意力调整也未推广至 GPU 1.7B：INT8 长录音回归出现后半段遗漏。1.7B 保留原卷积批次和文本注意力配置，仅使用上文已有的长输入音频注意力兼容修复。

CPU 解码缓存上限为 4096 token，避免原来的 1024-token 配置截断约 96 秒测试录音的音频输入；单次最多生成 512 token 不变。此调整增加 CPU 内存使用，不意味着任意长度录音都已通过完整性验收，也不替代录音期间的提前结算。

CPU 推理线程数不超过系统报告的逻辑处理器数量，最多为 4；无法获取处理器数量时保留 2 线程并记录警告。加载、切换模型和重载热词使用相同配置。4 线程已在开发机的长实录上验证文字不变且更快，但加速幅度取决于硬件和同时运行的其他工作。

## 热词与配置

在 `config/hotwords.txt` 中每行填写一个人名、产品名或专业术语。通过托盘的“打开热词文件”使用记事本编辑；关闭记事本进程后，VIM2 会比较打开前后的文件修改时间，仅在修改时间发生变化时自动加载新热词。编辑期间不会刷新；如果关闭时正在录音或识别，会在恢复就绪后加载。托盘中的“重新加载热词”仍可用于手动刷新。热词会提高相关词出现的概率，但不会强制替换识别结果。

- `config/settings.json`：模型、最长录音时间和实时预览设置。原有实时识别路径中，`preview_window_seconds` 控制单次预览最多使用的最近音频（默认 8 秒），`tail_overlap_seconds` 控制稳定句子边界前保留的重叠音频（默认 5 秒）；两者用途不同。GPU 0.6B 草稿路径采用上述 60 秒上限，不使用这两个切段设置。临时的数字后处理可通过 `normalize_numbers` 独立开关。
- `config/hotkey.conf`：全局热键，默认是 `RightAlt`。
- `config/hotwords.txt`：一行一个热词或短语。
