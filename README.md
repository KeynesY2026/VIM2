# VIM2

**按一下说话，再按一下，文字就出现在光标处。**

VIM2 是 Windows 本地语音输入工具。它能在记事本、浏览器、聊天软件、IDE 和远程桌面中工作。只需在自己的电脑安装一次，连接不同远程机器时无需重复安装模型。语音识别完全在本机完成，音频和文字不上传，也没有云服务费用。

> 当前支持 Windows 10/11 x64。macOS 支持正在路上。

[第一次使用：查看完整安装手册](INSTALLATION.md)

## 为什么选择 VIM2

- **真正离线：** 模型在本机运行，断网也能识别，语音不离开电脑。
- **一次安装，处处可用：** 连接多少台远程机器都不必重复部署，直接向当前远程桌面输入文字。
- **哪里都能输入：** 不局限于单个编辑器，最终文字直接粘贴到原来的光标处。
- **边说边看：** 录音过程中实时显示预览，停止后再生成可靠的最终文本。
- **中英混合：** 支持中文、英文、中英文混说以及多种中文方言。
- **硬件可选：** 有 NVIDIA GPU 可追求速度或精度，没有独显也能使用 CPU 模型。

## 启动

完成安装后，双击 `Start.cmd`。等待任务栏右下角的 VIM2 托盘图标变为绿色。

启动脚本完成检查并独立启动 APP 后立即退出，不会随 APP 一直驻留；APP 继续在系统托盘运行。

双击后没有反应时，查看 `runtime/vim2.log`。安装检查命令为：

```powershell
$env:PYTHONPATH = "$PWD\app"
python -m vim2 --check
```

## 使用

1. 点击任意应用中要输入文字的位置。
2. 按一次右 Alt 开始录音。
3. 再按一次右 Alt 停止；识别完成后文字会自动粘贴。
4. 在本地应用中，录音期间按 Esc 可取消，不会识别或粘贴文字。

右键单击托盘图标可以查看当前麦克风、切换输入设备或模型、编辑热词或退出。

“麦克风”菜单显示当前使用的输入设备，默认“跟随 Windows 默认”。每次开始录音前检查系统默认麦克风；如果在 Windows 中修改了默认输入，下次录音会使用新设备，并覆盖 APP 内此前的临时选择。默认未变化时，也可以在此菜单中临时选择其他麦克风，只影响 VIM2，不修改 Windows 设置。选择不保存，退出重开 APP 后恢复跟随默认。列表只显示 Windows 当前已连接且已启用的 WASAPI 输入设备，不再重复列出同一设备的其他音频接口；Windows 报告为可用的虚拟麦克风仍会显示。

设备名称后的“（系统默认）”表示 Windows 默认麦克风，菜单勾选表示 VIM2 当前的选择或“跟随 Windows 默认”模式；手动选择其他设备不会改变系统默认标记。

录音中不切换麦克风；请先停止录音，再选择设备。打开托盘菜单时会刷新空闲状态下的设备列表和系统默认标记，不做后台高频轮询。所选麦克风不可用时会明确提示，不会静默改用其他输入；可以从菜单选择另一个设备或恢复“跟随 Windows 默认”。

远程使用时，VIM2 仍然运行在自己的电脑上；请确认远程桌面或远控软件已允许剪贴板同步。远程机器不需要安装 VIM2、Python 或模型。部分 RDP 客户端会直接将 Esc 转发给远程系统，本机 VIM2 无法捕获，因此不支持在 RDP 窗口内使用 Esc 取消录音。

## 模型

| 模型 | 设备 | 特点 |
|---|---|---|
| Qwen3-ASR 0.6B INT8 | CPU | 默认，无需 NVIDIA 显卡 |
| Qwen3-ASR 0.6B FP16 | NVIDIA GPU | 速度和准确率均衡 |
| Qwen3-ASR 1.7B INT8 | NVIDIA GPU | 更高精度，处理速度较慢 |

程序一次只加载一个模型。可在托盘的“识别模型”菜单中切换，选择会自动保存。

超过 30 秒的 GPU 识别输入使用遵循模型音频分块边界的 SDPA 注意力，以改善长录音的识别完整性。30 秒以内的输入保留原有音频注意力路径；这是依据实录回归设置的兼容性边界，不代表所有时长的准确率已经验收。CPU ONNX 模型已在导出模型内处理音频分块，不需要 PyTorch 或额外的对齐模型。

GPU 0.6B 已启用录音期间的草稿验证加速，并采用低频、停顿感知的预览调度。首次预览收集至少 1 秒音频后触发（检查间隔不超过 500ms，目标约 2 秒内显示，实际取决于设备推理耗时）；后续两次启动至少间隔 5 秒，完成后至少休息 2 秒。较慢的推理还会按耗时延长休息，使连续预览推理的忙碌时间预算不超过约 60%；这不是 GPU 瞬时利用率、功耗或温度上限。失败后也遵守休息策略，不追赶旧刷新请求。停录立即封存录音并取消正在执行的预览，不等待预览休息计时结束。

GPU 0.6B 使用 `webrtcvad-wheels` 的低激进度语音活动检测，只分析新到达的 30ms 音频帧。停顿后至多补一次句尾预览，之后没有新语音就跳过重复推理；为避免轻声漏判，上次成功预览后有新的非零音频时，每 15 秒允许一次保守复核，不因窗口中保留的旧语音反复复核。检测只影响预览调度，不停止录音、不删除静音，也不以停顿锁定句子。CPU 与 GPU 1.7B 不使用此检测或新的预览节奏。

预览仍保留最近最多 60 秒的音频窗口。缩短到 15 秒并累积历史候选的实录试验出现术语退化；30 秒滑窗也出现过中途重复生成并触及生成上限，因此没有启用这些候选。降低负载优先依靠调度和停顿跳过，不以未经验证的短上下文替代原有识别路径。降低预览频率会让最终草稿较旧，部分录音的停录等待可能增加；不能保证每次录音都在 1 秒以内的额外延迟范围。

单次草稿最多 512 token，后续预览和最终识别仅复用最近一次成功草稿，不累积历史候选池。不保留预览 GPU 解码缓存，也不直接拼接预览为最终文本。后续预览和停录识别使用同一模型批量验证候选，最多验证 8 个位置，遇到不匹配立即回滚并逐词纠正；草稿不会强制覆盖最终文字。预填充只计算最后一行词表输出，保留完整隐藏状态和 KV。取消或失败的预览不覆盖成功草稿；新录音、取消、完成、重试、模型切换和热词重载会清理草稿。

本机九组数字音频回放中，95.758 秒和 149.235 秒样本的预览及调度墙钟开销分别由 87.46→57.10 秒、123.53→70.41 秒，下降约 35% 和 43%；最终识别耗时中位数分别为 18.76→18.83 秒、6.95→6.79 秒。七份 4.3—20.2 秒短录音的最终耗时中位数变化约为 -0.57 至 +0.70 秒，短录音基线复用同配置前轮结果，长录音采用同进程交错复测。九份中八份最终文字完全一致；95 秒样本有词句和笑声转写差异，并非只有标点不同。这不是人工 gold 准确率或错误概率评估。回放使用虚拟时间调度与真实 GPU 推理，未测风扇转速、温度或实际功耗，墙钟开销降幅不等于功耗降幅。

GPU 0.6B 超过 30 秒的输入还限制卷积批次最多为 16 个音频块，并显式展开文本注意力的 KV，避免 GQA 退回高内存计算路径；缓存验证使用已注册的 SDPA 因果掩码，不能让后续草稿词泄露到前面的预测。所有临时设置在成功、失败和取消后恢复。300 秒静音边界测试中，峰值 GPU 分配由约 4.27 GiB 降至 2.02 GiB，推理由约 125 秒降至 1.13 秒；静音不是长语音准确率证据。

此路径保留完整最终音频上下文，不依赖文本接缝切掉已识别音频，因此仍有音频编码和验证成本，并非停录后只编码尾段。约 96 秒实录的最终生产会话测试中，同进程完整识别为 25.60 秒，草稿加速为 15.34 秒（约快 40%），两者文字完全一致；相较此前原始基准，关键主线保留。草稿路径峰值 GPU 分配约 1.68 GiB，未发生 OOM。该数据不是任意时长或其他显存占用下的无 OOM 保证，也不是真实识别准确率评估。超过 512 token 且仍未结束的结果会明确报错并允许重试，不静默截断。CPU 和 GPU 1.7B 暂不启用草稿加速，保持原有实时识别路径。

GPU 1.7B 的隔离草稿实验在 25 秒实录上更快，但约 96 秒录音出现重复生成；增加生成预算、减小验证批次均未解决。关闭 INT8 异常值处理虽更快，却改变了关键归属语义，因此这些实验配置均未启用。不要以短片段加速结果替代长录音验收。

0.6B 的卷积批次和文本注意力调整也未推广至 GPU 1.7B：INT8 长录音回归出现后半段遗漏。1.7B 保留原卷积批次和文本注意力配置，仅使用上文已有的长输入音频注意力兼容修复。

CPU 解码缓存上限为 4096 token，避免原来的 1024-token 配置截断约 96 秒测试录音的音频输入；单次最多生成 512 token 不变。此调整增加 CPU 内存使用，不意味着任意长度录音都已通过完整性验收，也不替代录音期间的提前结算。

CPU 推理线程数不超过系统报告的逻辑处理器数量，最多为 4；无法获取处理器数量时保留 2 线程并记录警告。加载、切换模型和重载热词使用相同配置。4 线程已在开发机的长实录上验证文字不变且更快，但加速幅度取决于硬件和同时运行的其他工作。

## 热词与配置

在 `config/hotwords.txt` 中每行填写一个人名、产品名或专业术语。通过托盘的“打开热词文件”使用记事本编辑；关闭记事本进程后，VIM2 会比较打开前后的文件修改时间，仅在修改时间发生变化时自动加载新热词。编辑期间不会刷新；如果关闭时正在录音或识别，会在恢复就绪后加载。托盘中的“重新加载热词”仍可用于手动刷新。热词会提高相关词出现的概率，但不会强制替换识别结果。

- `config/settings.json`：模型、最长录音时间和实时预览设置。原有实时识别路径中，`preview_window_seconds` 控制单次预览最多使用的最近音频（默认 8 秒），`tail_overlap_seconds` 控制稳定句子边界前保留的重叠音频（默认 5 秒）；两者用途不同。GPU 0.6B 草稿路径保留上述 60 秒上限并采用独立负载预算，不使用这两个切段设置；`preview_interval_ms` 对它只控制轻量检查频率（最多 500ms 一次），不再代表每次检查都会推理。临时的数字后处理可通过 `normalize_numbers` 独立开关。
- `config/hotkey.conf`：全局热键，默认是 `RightAlt`。
- `config/hotwords.txt`：一行一个热词或短语。

## 开发

本机实录回归资料通过 `local-test-data/` 查看，整个入口由 `.gitignore` 排除，不提交到 Git：`audio/` 保存真人 WAV，`reports/` 保存历史及最终测试 JSON，`scripts/` 保存隔离实验脚本，`manifest.json` 记录原始位置、文件大小和 SHA-256。历史报告包括失败或已否决的方案，并不代表全部通过；脚本保留原样，部分仍依赖原会话路径或隔离环境。此目录不是运行应用所需文件，也不包含模型权重或依赖包。

当前项目位于 OneDrive 内，因此本机入口使用 Windows 目录联接，实际副本位于 `C:\Users\keynesy\AppData\Local\VIM2\local-test-data`，不直接存入 OneDrive 项目目录。目录联接和资料都不会随 Git 克隆创建。Git 忽略规则不是文件同步工具的排除设置；请勿让其他同步工具跟随此联接上传私人语音。
